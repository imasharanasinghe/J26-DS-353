## ABSTRACT

Online learning platforms usually give every student the same fixed order of lessons, no matter what the student already knows. Never tutoring systems built on large language models (LLM) can personalize this order and explain it in natural language, but they have a serious flaw: they sometimes place a topic before the topics it depends on, raise the difficulty too quickly, or fail to clear up common misconceptions. These mistakes do not look like mistakes – the path reads smoothly – yet they harm learning, because a student who meets a topic before they are ready gets stuck and may give up. This research proposes a neuro-symbolic middleware built on a pedagogy-typed knowledge graph. This report covers the individual component that generates the learning path.

The problem this component solves is that LLM-generated learning paths come with no guarantee that order is pedagogically correct. Existing solutions are not enough: some retrain a model using reinforcement learning, which needs large amounts of example data that barely exists, while others use a second LLM to check first, but that checker is just as unreliable. The gap this work fills is the lack of an education-specific symbolic checker that finds clear, labeled pedagogical errors and fixed the path one step at a time, without needing any training data.

The proposed contribution is a symbolic typed-violation critic. It checks an LLM drafted path against five pedagogical rules and returns specific, labeled violations, so the LLM can repair only the broken step. This runs inside a limited repair loop, backed by a guaranteed fallback tat always produces a valid path. Reinforcement learning is used only as an outer layer that guides the proposer and ranks already-verified paths; it never overrides the critic. The component is exposed through the team's REST API. The evaluation is experimental: the main measure is the prerequisite-violation rate before versus after the critic, supported by the critic's precision and recall and by convergence and fallback analysis, tested in the data-structures domain. Within the full solution, this component takes in the knowledge graph and the learner model and passes a verified path to the explanation component.

**Keywords:** neuro-symbolic AI; learning path generation; knowledge graph; typed-violation critic; verification.

## 1. INTRODUCTION

### 1.1 Background and Context

Most online learning platforms deliver the same fixed sequence of content to every learner, regardless of prior knowledge. Adaptive systems attempt to personalize this sequence, but the two dominant families each fall short. Rule-based and ontology-based systems respect prerequisite structure and are explainable yet cannot model individual learners well or explain recommendations in natural language. More recent LLM-based tutors are fluent and personalized, but they can hallucinate facts, ignore prerequisite structure, and provide no insight into why a given path was produced.

This individual component addresses the learning-path generation problem: given a learner's current state and a target concept, produce an ordered sequence of concepts to study. The people affected are learners (school, university, MOOC, and corporate), educators who design curricula, and the platforms that host them. A mis-ordered path is not a minor inconvenience — a learner who encounters a concept before its prerequisites become blocked and is at an elevated risk of disengagement.

#### Statical Evidence

Massive open online courses illustrate the scale of the problem. Across large datasets of courses, completion rates are consistently low: one comparative study of 221 MOOCs reported completion rates ranging from under 1% to about 52%, with a median of only 12.6% [X]. Reviews summarizing the field similarly report that MOOCs are typically completed by only 10–20% of enrolled students [Y], and analyses of individual courses have recorded drop-out rates as high as 80–95% [Z]. While drop-out is multi-causal, the literature links it directly to poor sequencing and lack of personalization: because prerequisite relationships enforce a rigid order, difficulty in mastering a single concept can cascade into broader disruptions along the learning path [W]. Conversely, adaptive systems that assess prior knowledge and tailor the path are associated with improved outcomes and fewer drop-outs [V]. This motivates the present component: if the order of concepts can be verified and corrected against prerequisite and difficulty constraints, one of the controllable contributors to disengagement is directly addressed.

#### Analysis of existing solutions (summary)

- Classical curriculum sequencers and reinforcement-learning path planners generate paths in a single pass and do not verify them against typed pedagogical constraints.
- LLM self-refinement loops (e.g. Self-Refine, Reflection) use a generic LLM as a critic, which offers no hard guarantee and no domain grounding.
- Recent constrained-RL tutoring methods align paths to pedagogy by retraining a model, which requires scarce demonstration data.

#### Proposed solution (C3 Part)

A symbolic typed-violation critic verifies an LLM-proposed path against five pedagogical rules and returns localized, typed violations that enable single-step repair, with a guaranteed algorithmic fallback. Reinforcement learning is added only as an outer layer that biases the proposer and reranks verified candidates.

#### SDG and research cluster alignment

This work aligns with UN Sustainable Development Goal 4 (Quality Education), specifically Target 4.1 (effective learning outcomes) and Target 4.4 (relevant skills for learning), by improving the correctness, personalization, and transparency of digital learning. By verifying that a learning path respects prerequisites and appropriate difficulty, the component directly targets a controllable contributor to learner disengagement, supporting more equitable and effective access to quality education — particularly for self-directed online learners who lack a human tutor to catch mis-sequenced content. This research falls under the Centre of Excellence in Artificial Intelligence (CoEAI) research cluster, as its core contribution is a neuro-symbolic AI method combining large language models, knowledge graphs, and symbolic verification.

### 1.2 Literature Review

The following review is organized around the three research streams the component draws on: learning-path recommendation, neuro-symbolic verifier loops, and LLM-based tutoring with pedagogical constraints. #### 1.2.1 Learning-path recommendation and knowledge graphs

Reinforcement learning has become the dominant paradigm for goal-oriented learning-path recommendations. Liu et al. proposed CSEAL, which uses deep knowledge tracing to estimate a learner's knowledge state and a cognitive-navigation algorithm over prerequisite relations to guide an actor–critic policy toward personalized paths [1]. Building on this line, Li et al. introduced GEHRL (Graph Enhanced Hierarchical Reinforcement Learning), which decomposes path recommendation into a high-level sub-goal selector and a low-level agent, uses a graph-based candidate selector to constrain the low-level agent's action space, and adds a test-based internal reward to alleviate sparse external rewards [2]. GEHRL was evaluated on standard knowledge-tracing datasets and improved goal-oriented path efficiency over single-agent baselines by reducing redundant items. However, both approaches share a limitation this research exploits: they generate paths in a single reinforcement-learning pass and enforce prerequisite structure only softly, through the reward or the candidate filter — the final path is never independently verified against typed pedagogical constraints, so violations remain possible in the output. More recent knowledge-graph-based planners face a related risk: because prerequisite relationships enforce a rigid sequence, difficulty in a single concept can cascade into broader disruption along the path, and graph construction itself can introduce hallucinated or misleading links [3]. This motivates a component that treats verification as a separate, explicit stage rather than folding it into a learned reward.

#### 1.2.2 Neuro-symbolic verifier / critic loops

A parallel line of work improves LLM outputs through iterative self-correction. Self-Refine (Madaan et al.) generates an initial output, then uses the same LLM to produce feedback and refine the output, looping until a stopping criterion is met, with no additional training or reinforcement learning [4]. Reflection (Shinn et al.) extends this by giving an agent a memory of self-reflections generated from a reward signal upon error detection, improving task-specific action selection [5]. Both were validated across reasoning and generation tasks and demonstrate that iterative critique can outperform single-pass generation. Their key limitation, from this component's perspective, is that the critic is generic: it is an LLM (or a scalar reward) with no domain grounding, so it offers no guarantee of correctness and cannot point to a specific, typed reason for a fault — indeed, some implementations regenerate the entire output each iteration rather than repairing a single step [6]. Kambhampati et al.'s LLM-Modulo framework formalizes the alternative followed here: separating LLM generation from external, sound verification, with the verifier — not the LLM — deciding validity [7]. LLM-Modulo is the parent framework this component instantiates for education, replacing its general-purpose verifier with an education-specific critic that returns typed pedagogical violations enabling single-step repair.

#### 1.2.3 LLM tutoring with pedagogical constraints

The closest rivals apply reinforcement learning to make LLM-generated paths pedagogically compliant. IB-GRPO (Wang et al.) aligns an LLM path recommender with objectives such as learning effect and Zone-of-Proximal-Development difficulty scheduling; to overcome scarce demonstrations it synthesizes hybrid expert data via genetic-algorithm search and teacher RL agents, warm-starts the LLM with supervised fine-tuning, and then optimizes a vector reward with an indicator-based policy [8]. It was evaluated on ASSIST09 and Junyi with a Qwen2.5-7B backbone. MC-CPO (Mastery-Conditioned Constrained Policy Optimization) enforces prerequisite feasibility structurally via a masked policy and optimizes a primal–dual Lagrangian with pedagogical-safety constraints, and its authors explicitly note that reward-based pedagogical objectives are hard to specify and prone to reward hacking [9]. These works confirm the importance of the problem but reveal the gap this component targets: both fix pedagogical compliance by retraining a model on demonstration data that is scarce and expensive, and their guarantee is statistical — a trained policy still can emit a violating path, only less often. In contrast, this component requires no training data, is model-agnostic, and enforces validity through a symbolic critic that makes violations detectable and repairable rather than merely less likely — and, notably, MC-CPO's own reward-hacking argument is direct evidence for preferring hard verification over learned reward.

### 1.3 Research Gap

Recent work makes LLM tutoring more reliable, but each approach falls short in a specific way. Verifier-in-the-loop methods add a check, but the verifier is either another unreliable LLM or a pass/fail gate that says only whether something is wrong, not what or where. Constrained-RL methods enforce prerequisites, but only by retraining a model on scarce demonstration data, and the guarantee is statistical — a violating path is less likely, not impossible. Generic self-refinement loops separate generation from verification, but their critic has no educational grounding and returns unstructured feedback. No existing system combines all the needed properties: a symbolic, education-specific critic that returns typed pedagogical violations for single-step repair, with no training data required.

**Research gap (one sentence):** there is no education-domain symbolic verifier that returns typed pedagogical violations to repair LLM-generated learning paths one step at a time, without training data, while remaining model-agnostic and transparent.

## 3. METHODOLOGY

### 3.1 Research Methodology and Design

The research question is causal and measurable-does adding a symbolic typed-violation critic reduce pedagogical violations in LLM-generated paths-so an experimental, quantitative design with controlled ablation is appropriate. The core comparison holds the proposer fixed and varies only the presence of the critic, isolating the critic's effect. This design suits the nature of the question, the quantitative outputs (violation rates, precision/recall), and the ablation-based norms of the neuro-symbolic and knowledge-tracing literature.

### 3.2 Data / Participants / Experimental Inputs

- **Knowledge graph:** a pedagogy-typed graph of the data-structures domain, supplied by the knowledge-graph component. For independent development, a hand-built mock graph is used until the real graph is available.
- **Learner state:** per-concept mastery and calibrated uncertainty from the student-model component; simulated learner states are used for the ablation where real states are unavailable.
- **Target concepts:** a held-out set of target concepts in the domain, used to generate and evaluate paths.

### 3.3 Baseline / Benchmark

- **Primary baseline:** the LLM proposer with no critic (proposer-only), on the same graph, learner states, and targets.
- **Secondary reference:** the algorithmic topological-sort path, representing a correct-but-impersonalized lower bound.

### 3.4 Evaluation Metrics

| Metric | Why relevant | Target / comparison |
|---|---|---|
| Prerequisite-violation rate | Directly measures the core problem — pedagogical correctness of ordering | Large reduction vs. proposer-only (headline result) |
| Critic precision / recall | Certifies the critic detects violations correctly | Logical rules → 100%; threshold rules reported with error rates |
| Convergence iterations | Shows the repair loop resolves violations efficiently | Converge within the 3-iteration bound in most cases |
| Fallback rate | Indicates whether rules conflict too often | Low fallback rate = loop is doing real work |
| Path coherence | Human/LLM-judge rating of overall path quality | Proposer + critic ≥ proposer-only |

*Table 2: Evaluation Metrices.*

### 3.5 Validation Strategy

Validity rests on three accepted practices. First, the critic is deterministic about code and is certified exhaustively by unit tests on inputs with known answers. Second, per-rule precision and recall are measured against a hand-labelled test set, following evaluation norms for verification systems. Third, the causal claim is validated by ablation — the only variable changed between conditions is the presence of the critic — so any reduction in violation rate is attributable to it. The guarantee is explicitly conditional: the critic is certified to enforce the graph rules correctly; the correctness of the graph edges is the knowledge-graph component's responsibility.

### 3.6 Development Approach

Iterative prototyping is selected. The component has clearly separable stages (frontier, proposer, critic, loop, fallback, reranked) that can be built and tested incrementally, and it depends on two upstream components, so building against mock inputs first and integrating later reduces risk. Each iteration adds one stage, is unit-tested, and is demonstrated at the scheduled progress reviews.

### 4.2 The Individual Component (Highlighted)

The individual component is organized as a layered pipeline (L0–L8). Reinforcement learning appears only as an outer optimization layer: it biases the proposer (L2) and reranks candidates (L6), but the symbolic critic (L4) alone decides validity. The invariant is that RL only ever selects among already-verified paths, so it can never produce or choose an invalid path.

**Component stages**

- **L0 Inputs** — validated DAG (from C1) and learner mastery + uncertainty (from C2).
- **L1 Frontier** — computes the admissible set of eligible next concepts, bounding the input handed to the proposer.
- **L2 RL policy** — offline IQL scores over the admissible set; biases the proposer toward higher-value concepts.
- **L3 Proposer** — LLM generates K candidate ordered paths.
- **L4 Critic** — checks five typed rules: prerequisites first; difficulty rises gently (ZPD); no loops / reachable; probe uncertain concepts; misconceptions first.
- **L5 Repair** — single-step repair of the offending step, bounded to three iterations.
- **L6 Reranked** — The RL value function selects the best path among verified candidates only.
- **L7 Fallback** — topological sort, guaranteeing a valid path if repair does not converge.
- **L8 Output** — verified ordered path + reasoning trace, passed to C4.

## 6. COMMERCIALIZATION PLAN

### 6.1 Target Market and Customer Persona

Our system is not a full learning platform on its own. It is a middleware — a service that plugs into learning platforms that already exist and makes their AI tutoring more trustworthy. So our customers are organizations that already run digital learning and want safer, more correct personalization.

The main customers are:

- Universities and colleges;
- LMS and MOOC providers (like the companies behind online course platforms);
- EdTech companies;
- Corporate training platforms.

We are not trying to sell to the whole online-learning market. We target the smaller group of platforms that already give digital courses, are adding AI tutoring, and want control over whether that tutoring is pedagogically and factually correct. The buyer is the platform or institution, not the individual student, because these integration decisions are made at the product or course level.

There is already proof this market is active. Coursera reported in 2024 that its AI assistant "Coach" had helped over one million learners, with a 9.5% higher first-try quiz pass rate and 11.6% more lessons finished per hour [X]. Khan Academy has also rolled out AI tutoring at large scale [Y]. These companies show that institutions want AI tutoring — and their own warnings about AI mistakes [Z] show they need the correctness checking our middleware provides.

The end users are learners, but the buyers are institutional teams — LMS administrators, EdTech product teams, course-platform operators, and education technology managers.

For the research prototype, we focus on one subject — Data Structures and Algorithms — with university students as the learners. But the design is reusable: give it a new subject's knowledge graph, and the same system works for that subject too.

**Customer persona:** a typical buyer is an LMS or EdTech product team that delivers courses to many learners and wants to add AI tutoring — but wants control over prerequisite order, difficulty, factual grounding, and learner-appropriate explanations. They would value a system they can connect through an API, without having to build the knowledge graph, learner model, path verifier, and explanation checker themselves.

### 6.2 Value Proposition

The main promise of the whole system is:

> To help learning platforms give personalized, prerequisite-aware, and explainable learning support — while reducing the mistakes that come from letting an LLM run unchecked.

The full system does this with four parts that share one knowledge graph: building the graph, modeling the learner, generating the verified path, and checking the explanation.

For my component (Component 3 — path generation) specifically, the promise is narrower:

> To make sure the learning path given to a student is in the correct order and rises in difficulty gently — by checking every path an LLM proposes against clear rules, and fixing any mistakes before the student sees it.

This is different from ordinary LLM path recommendation or reinforcement-learning approaches. Instead of assuming a smooth-looking path is a correct one — or training a model that only makes mistakes less likely — my component checks the path against real rules and fixes it. The check is a symbolic critic that reports exactly what is wrong, the path is repaired one step at a time, and a safe fallback always produces a valid order. So the correctness is guaranteed, easy to explain, and needs no training data.

The value to the customer includes:

- More trustworthy AI paths and explanations;
- Clear reporting of any prerequisite, difficulty, or misconception problems;
- Personalized ordering based on what the learner knows;
- Easy API integration with existing platforms;
- No need for the institution to build the whole checking system themselves.

## 11. Appendices

### Appendix 1 - Supporting Evidence

This appendix records the comparison notes built while narrowing down prior to learning-path generation approaches. GEHRL and IB-GRPO plan paths through reinforcement learning and enforce prerequisites only softly through the reward, so the final path is never independently verified; Self-Refine adds an iterative critic, but it is a generic LLM returning a vague judgment rather than a specific fault, and it regenerates the whole output each time. In contrast, this component verifies every proposed path with a symbolic critic that returns typed violations, repairs only the offending step, requires no training data, and guarantees a valid ordering through its fallback. As an example, on the mock data-structures graph the critic evaluated the candidate path Arrays → Linked Lists → Heaps → Trees for the target concept Heaps and returned two typed violations — a missing prerequisite (Heaps requires Trees) and a cognitive-load jump (Linked Lists to Heaps) — which drove the single-step repair that reordered the path.
